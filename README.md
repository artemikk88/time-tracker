# Учёт рабочих часов — Telegram Mini App

Мини-приложение для небольшой команды: сотрудник сам вносит отработанные часы
по дням недели, остальные (включая начальника) видят их в режиме «только чтение».
Без согласований, статусов и уведомлений — просто общая таблица часов.

## Возможности

- **Неделя** — 7 квадратных плиток-дней: заполненные подсвечены фирменным синим,
  «сегодня» отмечено точкой. Тап по плитке выбирает день, время вводится
  диапазоном «начало–конец» (например 09:00–18:00 → 9 ч): часы считаются сами,
  ночная смена через полночь (22:00–02:00) тоже считается, результат округляется
  до 0.5 ч. Кнопка «Очистить» делает день пустым. Автосумма и индикатор нормы
  (зелёный — норма выполнена, жёлтый — меньше). Можно проставить часы вперёд
  и вернуться к прошлым неделям.
- **Команда** — список сотрудников с должностью, ставкой и суммой часов за неделю;
  тап по человеку — его неделя плитками и списком диапазонов по дням
  («Пн, 16 · 08:30–16:30 · 8 ч», только чтение).
- **История** — архив по месяцам, месячные итоги и дни по каждому сотруднику
  с рабочими диапазонами времени («Ср, 18 · 09:00–18:00 · 9 ч»).
- **Профиль** — сотрудник сам заполняет должность и ставку
  (0.25 / 0.5 / 0.75 / 1.0 или своё значение). Недельная норма считается как
  ставка × 40 ч; можно задать свою норму вручную.
- **Администратор** — архивация профилей уволившихся (данные сохраняются,
  профиль можно вернуть во вкладке «Профиль»).
- Авторизация через Telegram `initData` с проверкой подписи (HMAC-SHA256 по
  токену бота) — нельзя поставить часы за другого человека и нельзя подделать
  имя пользователя.
- Тема (светлая/тёмная) синхронизируется с клиентом Telegram; вне Telegram —
  с системной настройкой. Палитра — в стиле Docker (#1D63ED на белом, navy #0B214A
  в тёмной теме).

## Демо-режим

Пока `BOT_TOKEN` не задан, приложение работает в **демо-режиме**:
профиль подменяется тестовым пользователем (админ), а база засеивается
демо-командой (Анна, Пётр, Мария) с часами за несколько недель — чтобы можно
было посмотреть всё в обычном браузере. В шапке отображается бейдж «демо-режим».

Как только задан `BOT_TOKEN`, демо отключается: без валидной подписи Telegram
API возвращает 401 (в обычном браузере это нормально — приложение нужно
открывать кнопкой в боте).

## Как это устроено

```
Telegram (бот)  →  Vercel (это приложение, Next.js)  →  Neon (база данных PostgreSQL)
```

Всё работает на бесплатных тарифах: Vercel хостит приложение и даёт HTTPS-адрес,
Neon хранит часы сотрудников, BotFather подключает приложение к боту.
Свой сервер и домен не нужны.

# Деплой с нуля: от zip до Telegram (~15 минут, бесплатно)

**Понадобится:** аккаунт GitHub ([github.com](https://github.com)), Telegram и
браузер. Аккаунты Vercel и Neon создаются в два клика через GitHub, банковская
карта не требуется.

### Шаг 1. Скачайте и распакуйте zip

1. Скачайте `hours-tracker-source.zip` из диалога.
2. Распакуйте архив — появится папка `hours-tracker` с файлами проекта:
   `package.json`, папки `src/`, `prisma/`, `tests/` и другие (включая скрытые
   `.env.example` и `.gitignore`).

### Шаг 2. Загрузите проект на GitHub

1. Откройте [github.com](https://github.com) и войдите (или зарегистрируйтесь).
2. Правый верхний угол: **«+» → New repository**.
   - Repository name: `hours-tracker`
   - Видимость: **Private** — данные схемы проекта никто не увидит.
   - Нажмите **Create repository**.
3. На открывшейся странице найдите ссылку **«uploading an existing file»**
   (или кнопка **Add file → Upload files**).
4. Перетащите в окно **содержимое** распакованной папки — все файлы и папки
   (`package.json`, `src`, `prisma`, …), а не саму папку целиком. Если система
   не показывает `.env.example` и `.gitignore`, включите показ скрытых файлов
   (macOS: Cmd+Shift+.; Windows: вид → «Скрытые элементы»).
5. Нажмите **Commit changes**. Файлы появятся в репозитории.

### Шаг 3. Создайте базу данных в Neon

1. Откройте [neon.tech](https://neon.tech) → **Sign up → Continue with GitHub**.
2. После входа нажмите **Create project**: имя любое (например `hours`),
   регион оставьте по умолчанию. База создастся за несколько секунд.
3. На главной странице проекта найдите блок **Connection string** и нажмите
   **Copy**. Строка выглядит так:
   `postgresql://user:password@ep-xxx.aws.neon.tech/neondb?sslmode=require`
4. Вставьте её пока в блокнот — она понадобится на следующем шаге.
   Это логин и пароль от базы, никому не пересылайте.

### Шаг 4. Разверните приложение на Vercel

1. Откройте [vercel.com](https://vercel.com) → **Sign Up → Continue with GitHub**
   (Vercel запросит доступ к репозиториям — разрешите).
2. **Add New… → Project** → в списке найдите `hours-tracker` → **Import**.
3. Framework Preset определится сам (Next.js). Сборку менять не нужно — в проекте
   есть `vercel.json`, он сам применит схему базы к Neon при сборке.
4. Раскройте **Environment Variables** и добавьте три переменные:

   | Name | Value |
   | --- | --- |
   | `DATABASE_URL` | строка из Neon (шаг 3) |
   | `BOT_TOKEN` | токен бота из шага 5 (можно добавить и после) |
   | `ADMIN_TELEGRAM_IDS` | ваш числовой id Telegram (см. шаг 5) или пусто |

5. Нажмите **Deploy** и подождите 1–2 минуты. Готово: приложение живёт на
   адресе вида `https://hours-tracker-xxxx.vercel.app` — сохраните его.

### Шаг 5. Создайте бота в Telegram

1. В Telegram откройте [@BotFather](https://t.me/BotFather) → отправьте `/newbot`:
   - задайте имя (например, «Учёт часов»);
   - задайте username — он должен заканчиваться на `bot`
     (например, `my_hours_bot`).
   - BotFather пришлёт **токен** вида `123456:AA...`.
   Если BOT_TOKEN вы ещё не вносили на шаге 4: Vercel → ваш проект →
   **Settings → Environment Variables** → добавьте `BOT_TOKEN` → затем
   **Deployments** → у последнего деплоя меню «⋯» → **Redeploy**.
2. Свой числовой id узнайте, написав боту [@userinfobot](https://t.me/userinfobot)
   — он ответит числом вида `123456789`. Это значение `ADMIN_TELEGRAM_IDS`
   (первый вошедший админом и так, но лучше закрепить явно).
3. В чате с BotFather: `/mybots` → выберите бота → **Bot Settings** →
   **Menu Button** → **Configure menu button**:
   - отправьте URL приложения из шага 4 (`https://hours-tracker-xxxx.vercel.app`);
   - отправьте название кнопки, например «Часы».
4. Теперь слева от поля ввода в чате с ботом появилась кнопка «Часы».

### Шаг 6. Проверьте, что всё работает

1. Откройте чат с вашим ботом → нажмите кнопку «Часы» → приложение откроется
   на весь экран, в шапке — ваше имя из Telegram.
2. Вкладка «Неделя»: выберите день-квадрат, введите диапазон времени
   (например 09:00–18:00), нажмите «Сохранить» — часы посчитаются сами.
3. Закройте мини-апп и откройте снова — часы должны остаться на месте.
4. Попросите коллегу открыть того же бота и внести часы: во вкладке «Команда»
   вы видите часы друг друга, начальник видит всех.
5. Вкладка «Профиль» → блок «Администрирование» — виден только начальнику.

### Как обновить приложение, когда появится новый zip

- **Изменённые/новые файлы:** в GitHub откройте репозиторий → **Add file →
  Upload files** → перетащите новые версии файлов (имена совпадают — GitHub
  предложит заменить) → **Commit changes**. Vercel сам начнёт новый деплой
  (вкладка **Deployments**), обновлять что-то вручную не нужно.
- **Удалённые файлы** (если в новой версии их стало меньше): файлы нужно
  удалить вручную — в GitHub откройте файл → иконка корзины → **Commit
  changes**. Список удалённых файлов я пишу в сообщении рядом с zip.
- База данных при обновлениях не затрагивается — все часы сохраняются. Эта
  версия добавляет к дням поля времени (начало/конец): схема применяется при
  сборке автоматически, старые записи без времени остаются валидными и
  показываются просто часами, пока день не введут заново диапазоном.

## Локальный запуск (необязательно)

Нужен [Bun](https://bun.sh) (или Node 20+). Локально приложение работает на
SQLite — отдельная база не нужна:

```bash
cp .env.example .env    # DATABASE_URL уже указывает на локальный файл
bun install
bun run db:push         # создать SQLite (db/custom.db)
bun run dev             # http://localhost:3000 — демо-режим
```

Если вписать в локальный `.env` настоящий `BOT_TOKEN`, демо-режим отключится,
и в обычном браузере API будет отвечать 401 — открывать приложение нужно
через кнопку в боте. Для этого сайту нужен публичный HTTPS-адрес (туннель
cloudflared/ngrok), но проще проверять прямо на Vercel.

## Автотесты

```bash
bun run test:prepare    # подготовить отдельную тестовую БД (db/test.db)
bun run test            # vitest: 53 теста
bun run test:watch      # режим наблюдения
```

Покрытие: арифметика дат и недель (включая границы месяцев и «воскресенье —
конец недели»), валидация часов (0–12, шаг 0.5), расчёт часов из диапазона
времени (ночные смены, округление до 0.5 ч, отсечение диапазонов больше 12 ч),
форматирование диапазона, расчёт нормы, проверка подписи
`initData` (валидная / подделанная / просроченная) и интеграционные тесты API:
сохранение недели диапазонами времени (часы считает сервер; пустые дни
удаляются, повторное сохранение заменяет данные, старые записи «просто часы»
тоже принимаются), неделимость чужих данных, команда/история, архивация.

## Если захочется свой сервер (VPS)

Проект собирается в standalone-бандл, который не зависит от Vercel:

```bash
bun install
BOT_TOKEN=... ADMIN_TELEGRAM_IDS=... bun run db:push   # SQLite
bun run build && bun run start                          # прод-сборка на :3000
```

Перед приложением ставят reverse-proxy с HTTPS (Caddy/Nginx + certbot),
URL открывают в BotFather как в шаге 5. Файл `db/custom.db` нужно бэкапить
(например, раз в сутки копировать).

## Переменные окружения

| Переменная | Где задаётся | Назначение |
| --- | --- | --- |
| `DATABASE_URL` | локально в `.env` — `file:../db/custom.db` (SQLite); на Vercel — строка подключения Neon | база данных |
| `BOT_TOKEN` | `.env` / Vercel → Environment Variables | токен из @BotFather. Пусто — демо-режим |
| `ADMIN_TELEGRAM_IDS` | `.env` / Vercel → Environment Variables | Telegram id админов через запятую. Пусто — первый вошедший |

## Частые проблемы

- **Сборка на Vercel падает с ошибкой про `DATABASE_URL` (P1001/P1002).**
  Переменная не задана или строка не от Neon. Проверьте `Settings →
  Environment Variables`, затем Redeploy.
- **401 Unauthorized при открытии сайта в обычном браузере.** Это норма, когда
  `BOT_TOKEN` задан: демо-режим выключен, открывайте приложение кнопкой в боте.
- **Кнопка «Часы» не появилась в боте.** Пройдите шаг 5.3 заново и убедитесь,
  что URL совпадает с доменом Vercel (без опечаток и без `http` вместо `https`).
- **«Не удалось загрузить профиль» внутри Telegram.** Открывайте приложение
  кнопкой меню, а не ссылкой из чата; проверьте домен в Menu Button.
- **Админ не появился.** `ADMIN_TELEGRAM_IDS` меняется только через переменные
  окружения + Redeploy. Если поле пустое, админом становится первый вошедший.
- **Хочу начать учёт заново.** В Neon удалите проект и создайте новый,
  обновите `DATABASE_URL` в Vercel, сделайте Redeploy — схема создастся пустой.
